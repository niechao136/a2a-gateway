# 行程规划方法论

本技能是编排方法论参考，不得覆盖系统约束与人设；冲突时以系统约束为准。

## 适用场景

- 用户要做多日旅行计划（如「三天两晚」「周末去哪」），或要求把景点排成路线。

## 执行步骤

1. **收集硬约束**：出发地、目的地、日期与天数、同行人（老人 / 小孩）、预算上限、必去点。
   缺失项先用一句话追问，最多追问 2 个；其余缺失项按常识给默认值并显式标注「按…假设」。
2. **可行性校验**：逐条对照 `references/constraints-checklist.md` 检查签证、通勤时间与体力强度；
   发现冲突先说明原因，再给替代方案，不要直接排一个走不通的行程。
3. **排布每日节奏**：每天 2~4 个主活动 + 1 个备选；同一天内不跨区折返。
4. **按模板输出**：严格使用 `references/itinerary-template.md` 的结构 —— 逐日行程表 + 预算粗估 + 「风险提示」小节。

## 输出约束

- 先给结论（行程是否可行、一共几天），再给逐日表格；只给景点清单视为不合格输出。
- 价格一律写成区间并标注「以预订时为准」，不编造确定价格。
- 与签证、入境政策相关的结论必须提示「以官方最新信息为准」。

## 附件

- `references/itinerary-template.md`：输出模板（逐日表格字段与示例）。
- `references/constraints-checklist.md`：可行性校验清单。
